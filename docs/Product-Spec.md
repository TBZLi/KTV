# 声域友 KTV 点歌系统 - 产品需求文档

> 版本：1.9.0
> 最后更新：2026-05-14
> 项目性质：Web 应用学科课程作业（团队项目）

---

## 1. 项目概述

### 1.1 产品名称
声域友（Hydro-Sonic Canvas / Azure Echo）

### 1.2 产品定位
一套面向 KTV 场馆的**点歌管理系统**，包含面向运营人员的管理后台和面向顾客的点歌前端。通过 Web 应用替代传统 KTV 点歌终端，实现歌曲浏览、点歌排队、房间管理、订单结算等核心流程的在线化。

### 1.3 产品目标
- 将课程作业中的原型设计完整落地为可运行的全栈 Web 应用
- 管理端覆盖 KTV 日常运营所需的全部管理功能（房间、歌曲、订单、账户、设置）
- Web 端覆盖顾客在包厢内的核心使用场景（选歌、点歌、排队、收藏）

### 1.4 项目范围
- **包含**：管理端 6 个页面 + Web 端 5 个页面 + 后端 RESTful API + 数据库设计
- **不包含**：支付网关对接、移动端适配、多租户 SaaS 架构

---

## 2. 目标用户

### 2.1 管理端用户 — KTV 运营人员

| 属性 | 描述 |
|------|------|
| 角色 | KTV 店长 / 前台 / 运营管理员 |
| 技术水平 | 会基本电脑操作，无需技术背景 |
| 使用场景 | 日常营业中管理房间状态、处理订单、维护歌曲库、管理用户账户、查看营业数据 |
| 核心痛点 | 需要一个统一后台查看和管理所有运营数据，而非多个分散的系统 |

### 2.2 Web 端用户 — KTV 顾客

| 属性 | 描述 |
|------|------|
| 角色 | 在 KTV 包厢消费的顾客 |
| 技术水平 | 普通手机/电脑用户 |
| 使用场景 | 在包厢内通过浏览器浏览歌曲库、搜索点歌、查看播放队列、管理个人收藏 |
| 核心痛点 | 传统 KTV 点歌机界面陈旧、操作卡顿、歌曲搜索不智能 |

## 3. 核心功能

### 3.1 管理端功能

#### 3.1.1 仪表盘

**功能描述**：运营人员登录后看到的首页，展示关键运营指标概览。

**输入**：无（自动加载）

**输出**：
- 4 张统计卡片：总包厢数、今日订单数、总收入（¥）、活跃用户数
- 总收入支持时间维度筛选：今日 / 本周 / 本月 / 自定义日期范围
- 最新订单列表（订单号、包厢、金额、状态、时间，展示最近 5 条）
- 热门歌曲排行（排名、封面、歌曲名、歌手、播放量，展示 Top 5）

**业务规则**：
- 统计卡片数据实时从数据库聚合查询
- 总收入计算：SUM(amount) WHERE status IN ('in_progress', 'completed')，排除已退款、已取消、已删除记录
- 收入金额以人民币（CNY）显示，保留两位小数
- 订单状态分为：进行中（蓝色）、已完成（绿色）、已取消（灰色）
- 排行榜按累计播放量降序排列

**优先级**：高

---

#### 3.1.2 房间管理

**功能描述**：管理 KTV 包厢的基本信息和实时状态。

**输入**：
- 筛选条件：状态（全部 / 使用中 / 空闲 / 打扫中）
- 搜索条件：包厢号关键字

**输出**：
- 包厢列表表格：包厢号、类型、状态、当前订单号、操作按钮
- 包厢类型：VIP 包厢（V 前缀，金色标签）、中包厢（M 前缀，蓝色标签）、小包厢（S 前缀，灰色标签）
- 状态标签：使用中（绿色）、空闲（蓝色）、打扫中（金色）

**业务规则**：
- 包厢号格式：类型前缀 + 三位数字，如 V-001、M-012、S-005
- 支持查看包厢详情和手动结束当前使用会话
- 操作列提供状态切换按钮：使用中→结束会话（变打扫中）、打扫中→变空闲
- 新建订单时，订单号自动绑定到对应房间的"当前订单"字段
- 结束会话后，包厢状态自动变为"打扫中"，"当前订单"清空
- 打扫中状态可通过操作按钮一键切回"空闲"

**优先级**：高

---

#### 3.1.3 歌曲管理

**功能描述**：维护歌曲库的增删改查，包含歌曲列表、新增歌曲弹窗、歌曲详情页三个层级。

---

**3.1.3.1 歌曲列表**

**输入**：
- 搜索：按歌曲名或歌手名模糊搜索
- 筛选：按流派分类筛选

**输出**：
- 3 张统计卡片：总曲目数、本周新增数、今日播放量
- 歌曲列表表格：封面缩略图、歌曲名、歌手、流派、状态、操作按钮（详情 / 删除）
- 支持分页浏览

**业务规则**：
- 歌曲状态分为：已上架（可被点歌）、已下架（不可见）
- 删除为软删除（状态标记为 disabled），不物理删除数据
- 流派预设值：流行、摇滚、民谣、电子、R&B、嘻哈、古典
- 时长以"分:秒"格式展示，存储以秒为单位
- 操作列："详情"按钮跳转到歌曲详情页，"删除"按钮触发确认弹窗后软删除

---

**3.1.3.2 新增歌曲弹窗**

**触发方式**：歌曲列表页点击"新增歌曲"按钮

**输入**：
- 歌曲名称（文本，必填）
- 歌手（文本，必填）
- 风格（下拉选择，必填，预设值同流派列表）
- 语种（下拉选择，必填，预设值：中文、英文、日文、韩文、其他）
- 音乐文件（文件上传，必填）
  - 接受格式：.mp3
  - 最大大小：30MB
  - 上传接口：`POST /api/upload/music`
  - 上传后返回 `url`，存入 `MediaUrl` 字段
- 封面图片（文件上传，可选）
  - 接受格式：.jpg, .jpeg, .png, .webp
  - 最大大小：5MB
  - 上传接口：`POST /api/upload/cover`
  - 未上传时使用默认封面 `/uploads/covers/default.jpg`
  - 文件丢失回退规则见 3.3 图片资源回退规则

**自动填充**：
- 时长（秒）：从上传的 MP3 文件自动读取，填入 `Duration` 字段
- 文件大小：从上传文件自动获取，填入 `FileSize` 字段
- 歌名和歌手：按以下优先级自动识别（仅新增模式，且对应字段为空时触发）
  1. **ID3 标签**：读取 MP3 文件内嵌的 `title` 和 `artist` 字段
  2. **文件名拆解**：ID3 标签缺失时，按 ` - `（减号两侧空格）拆分文件名，前半为歌手、后半为歌名；同时去除方括号标签（如 `[mqms]`）和扩展名
  3. 兜底：歌名取清理后的文件名，歌手留空
  - 详情页替换音乐文件时不触发此逻辑
- 封面图：从 MP3 文件 ID3 标签内嵌图片自动读取（仅新增模式，且封面为空时触发）
  - 读取成功后自动上传到服务器，填入封面字段
  - 无内嵌图片则跳过，不报错

**输出**：
- 上传过程中显示上传进度
- 上传成功后封面显示缩略图预览
- 保存成功后关闭弹窗，刷新歌曲列表

**业务规则**：
- 音乐文件为必填项，封面为可选项（未设置时使用默认封面 default.jpg）
- 文件上传与歌曲信息保存为两步：先上传文件获取 URL，再提交歌曲表单
- 文件上传失败时不提交表单，显示错误提示
- 时长从 MP3 文件 ID3 标签或文件头自动解析，无需用户手动输入
- 保存成功后关闭弹窗，刷新歌曲列表

---

**3.1.3.3 歌曲详情页**

**触发方式**：歌曲列表页点击某行的"详情"按钮

**展示字段（只读模式）**：

| 字段 | 来源 | 说明 |
|------|------|------|
| 封面 | `CoverUrl` | 大尺寸展示，无封面或文件丢失按 3.3 规则回退 |
| 歌曲名称 | `Title` | — |
| 歌手 | `Artist` | — |
| 文件大小 | `FileSize` | 上传时自动记录，格式化显示（如 4.2 MB） |
| 时长 | `Duration` | 格式化为"分:秒" |
| 风格 | `Genre` | — |
| 语种 | `Language` | — |
| 播放量 | `PlayCount` | 只读，实时数据 |
| 收藏数 | `Favorites` 表 COUNT | 实时查询，不存储冗余字段 |
| 评分 | 占位数据 | 展示字段，当前硬编码为 0 |
| 评论数 | 占位数据 | 展示字段，当前硬编码为 0 |
| 榜单排行 | 根据 `PlayCount` 实时计算 | 按播放量降序排名，显示当前排名 |
| 状态 | `Status` | 已上架 / 已下架 |
| 创建时间 | `CreatedAt` | 格式化展示 |

**修改模式**：
- 点击"修改"按钮进入编辑模式，"修改"按钮变为"保存"和"取消"
- 可修改字段：
  - 封面：可重新上传替换，上传接口同新增流程
  - 歌曲名称、歌手、风格、语种：文本/下拉直接修改
- 音乐文件替换：
  - 允许替换（支持换同首歌不同品质的场景）
  - 点击"替换音乐"按钮触发文件选择
  - 选择后弹出确认弹窗："替换后原文件将被删除，确定继续？"
  - 确认后上传新文件，删除旧文件，时长和文件大小自动更新
- 不可修改字段：播放量、收藏数、评分、评论数、榜单排行、创建时间

**业务规则**：
- 详情页为独立页面（非弹窗），从歌曲列表点击进入
- 详情页提供"返回列表"按钮
- 评分和评论数当前为占位展示（值为 0），未来有完整功能时再对接真实数据
- 收藏数通过 `SELECT COUNT(*) FROM Favorites WHERE SongId = @id` 实时查询
- 榜单排行通过 `SELECT COUNT(*) + 1 FROM Songs WHERE PlayCount > @playCount AND Status = 'active'` 实时计算
- 替换音乐文件时，先上传新文件成功后再删除旧文件，避免数据丢失
- 封面和音乐文件的旧文件在替换后从服务器物理删除（`wwwroot/uploads/` 下对应的文件）

---

**优先级**：高

#### 3.1.4 订单管理

**功能描述**：查看和管理所有房间消费订单。

**输入**：
- 筛选条件：订单状态（全部 / 进行中 / 已完成 / 已取消 / 已退款）、日期范围
- 搜索：下拉菜单切换搜索方式（订单号 / 用户名 / 包厢号），输入关键字模糊搜索
- 新建订单：用户 ID、房间 ID、使用时长（小时）或自定义金额

**输出**：
- 订单列表表格：订单号、包厢号（含类型）、用户名、金额、状态、创建时间、操作按钮
- 订单号格式：ORD-XXXX（如 ORD-8924）
- 所有列表展示使用人类可读名称（包厢号、用户名），不展示数据库 ID
- 创建时间精确到秒级，使用北京时间（UTC+8）

**新建订单金额计算规则**：
- 默认方式：填写使用时长（小时），金额 = 小时数 × 单价基数 × 包厢类型倍率 × 节假日倍率（如适用）
- 单价基数：系统设置中的"默认包厢单价基数"
- 包厢类型倍率：VIP 1.5x、中包 1.3x、小包 1.0x（可在系统设置中调整）
- 节假日倍率：仅在节假日动态定价开启且当前日期处于节假日范围内时叠加
- 前端新建订单时，根据所选包厢实时显示对应的实际单价（如"180.00/小时（1.5x）"）
- 自定义金额（二级选项）：勾选"自定义金额"后，直接输入金额，不按时长计算
- 自定义金额优先级最高，适用于特殊情况（包场、折扣等）

**订单操作**：
- 完成：订单标记为已完成，扣款生效，房间状态变为"打扫中"
- 取消：订单标记为已取消，退款至用户账户，房间状态变回"空闲"
- 退款：订单标记为已退款，退款至用户账户，房间状态变回"空闲"
- 删除：仅终态订单（已完成 / 已取消 / 已退款）支持删除，软删除标记，需二级密码验证（输入当前管理员密码确认）
- 恢复：仅"已取消"状态的订单支持恢复，恢复后订单状态变回"进行中"，房间重新绑定该订单，用户余额重新扣款，需确认弹窗

**业务规则**：
- **每个用户同一时间只能有 1 个"进行中"状态的订单**。新建订单时，用户下拉选项中已有进行中订单的用户不可选（置灰或隐藏），并提示"该用户已有进行中订单"
- **VIP 包厢仅限 VIP 用户使用**。新建订单选择包厢时，如果当前用户不是 VIP，VIP 包厢选项不可选（置灰），并提示"该包厢仅限 VIP 用户使用"
- 订单状态流转：进行中 → 已完成 / 已取消 / 已退款；已取消 → 进行中（恢复）
- 仅"进行中"状态的订单支持完成、取消、退款操作
- 仅终态订单支持删除操作，进行中订单不可删除
- 仅"已取消"订单支持恢复操作
- 完成操作不退款，取消和退款操作退款至用户账户
- 恢复操作从用户余额重新扣款（退款金额 = 恢复扣款金额）
- 操作完成后，房间的"当前订单"字段自动更新（取消/退款/删除清空，恢复重新绑定）
- 已删除订单不在列表中展示，不参与仪表盘统计
- 金额以人民币显示，保留两位小数
- 订单创建时间精确到秒级，记录北京时间

**搜索功能**：
- 搜索框旁提供下拉菜单，可切换搜索方式
- 搜索方式：按订单号搜索、按用户名搜索、按包厢号搜索
- 每种搜索方式均为模糊匹配
- 切换搜索方式时清空搜索框

**优先级**：高

#### 3.1.5 账户管理

**功能描述**：管理顾客账户信息、余额和访问权限。

**输入**：
- 搜索：按用户名搜索
- 筛选：状态（全部 / 启用 / 禁用）
- 新增账户：用户名、密码、昵称、手机号

**输出**：
- 用户列表表格：用户名（含头像）、余额、VIP 标签、状态、创建时间、操作按钮
- VIP 用户显示"高级会员"金色标签
- 已禁用用户行降低透明度

**业务规则**：
- 用户状态：启用 / 禁用
- 支持余额调整操作：正数 = 充值，负数 = 扣款
- 余额调整需二级密码验证（输入当前管理员密码确认）
- **VIP 状态切换**：通过用户编辑弹窗中的 VIP 下拉框修改，切换时需二级密码验证（输入当前管理员密码确认），与删除订单、余额调整的验证流程一致
- 支持启用/禁用用户账户切换，点击禁用时弹出确认提示
- 如果该用户有进行中订单，确认弹窗显示"该用户有 X 个进行中订单，禁用后将全部取消并退款。确认禁用？"；如果没有进行中订单，只显示普通确认"确认禁用该用户？"
- 禁用后，该用户所有进行中订单自动标记为"已取消"，退款至用户余额
- 被禁用用户不出现在新建订单的用户下拉选项中
- VIP 用户与普通用户在管理端仅标签区分，权限差异在业务逻辑中处理

**优先级**：高

---

#### 3.1.6 系统设置

**功能描述**：配置 KTV 门店的基础运营参数、节假日定价、操作日志查看及敏感操作验证策略。

**输入/输出**（六个配置区块）：

**区块 1 - 管理员账号**：
- 管理员用户名（文本，修改需密码确认）
- 修改管理员密码（输入当前密码 + 新密码 + 确认密码）

**区块 2 - 基本信息**：
- 店铺名称（文本）
- 联系电话（文本）
- 店铺地址（文本）
- 营业时间（文本，如"14:00 - 02:00"）

**区块 3 - 定价设置**：
- 默认包厢时薪（数字，单位：元/小时）
- 包厢类型倍率（三个数字输入框，步长 0.1，最小值 0.1）
  - VIP 包厢倍率（默认 1.5）
  - 中包厢倍率（默认 1.3）
  - 小包厢倍率（默认 1.0）
  - 实际单价 = 单价基数 × 包厢类型倍率
- 节假日动态定价（开关）
- 节假日日期管理（列表，支持新增/删除日期范围）
  - 新增节假日：日期范围选择器（开始日期 ~ 结束日期），如"2026-10-01 ~ 2026-10-07"
  - 节假日列表展示：日期范围 + 倍率信息 + 删除按钮
- 节假日倍率设置（每个包厢类型独立设置）：
  - VIP 包厢倍率（数字，默认 1.5）
  - 中包厢倍率（数字，默认 1.3）
  - 小包厢倍率（数字，默认 1.2）

**区块 4 - 安全设置**：
- 日志保留期限（下拉选择：30天 / 90天 / 180天 / 永久）
- 敏感操作二次验证（勾选制，可按操作类型独立配置）
  - 可配置项：删除订单、余额调整、禁用/启用用户、切换用户 VIP 状态、批量上下架歌曲、修改系统设置、修改管理员账号
  - 每项为独立复选框，默认全部勾选
  - 开启后对应操作需输入当前管理员密码二次确认

**区块 5 - 操作日志**：
- 日志列表（分页展示，所有管理员可查看）
  - 展示字段：时间、操作人、操作类型、操作对象、详情
  - 筛选条件：操作类型（下拉选择）、日期范围、操作人（下拉选择）
  - 记录的操作类型：创建/修改/删除订单、余额调整、禁用/启用用户、切换 VIP 状态、上下架歌曲、修改房间状态、修改系统设置、登录/登出
- 日志保留规则：按区块 4 中设置的日志保留期限自动清理过期日志

**业务规则**：
- 管理员账号在系统设置中单独管理，不在账户管理列表中展示
- 管理员账号不可禁用，禁用操作仅对普通用户生效
- 修改管理员用户名或密码需密码验证（输入当前密码）
- 节假日动态定价仅在开关开启且当前日期处于已配置的节假日范围内时生效
- 节假日倍率默认值为 1.0（不涨价），管理员可调整
- 节假日价格 = 包厢默认时薪 × 节假日倍率
- 节假日日期范围支持重叠（取最高倍率）和连续（如跨年假期）
- 操作日志为只读展示，不可修改或删除
- 操作日志在每次成功执行操作后自动写入，异步写入不影响主流程性能
- 敏感操作二次验证的配置修改本身也属于敏感操作（防止恶意关闭验证）
- 所有设置以键值对形式存储在数据库中
- 修改后点击"保存设置"按钮生效
- 保存成功后显示确认提示

**优先级**：中

#### 3.2.6 底部播放器栏（全局组件）

**功能描述**：所有 Web 端页面（除登录页）底部固定显示的播放控制栏，基于 HTML5 `<audio>` 实现真实音频播放，切页面不中断。

**数据来源**：
- 播放队列：当前房间的已点歌曲列表
- 音频 URL：歌曲的 `MediaUrl` 字段，指向 `wwwroot/uploads/music/` 下已上传的 MP3 文件

**输出**：
- 左侧：当前播放歌曲信息（标签"Playing" + 歌曲名 + 歌手名）
- 中间：播放控制按钮（上一首 / 播放/暂停 / 下一首）
- 右侧：音量滑块
- 底部：进度条（可拖拽），显示当前时间 / 总时长
- 顶部：渐变色装饰线（primary → secondary）

**空队列状态**：
- 播放器栏始终显示，不隐藏
- 歌曲信息区显示占位文字"未在播放"
- 播放/暂停按钮置灰，不可点击
- 进度条和音量滑块置灰

**播放行为**：
- 点击"点歌"：歌曲加入播放队列；若队列此前为空（播放器处于空队列状态），自动播放该歌曲
- 播放队列中有多首歌曲时，当前歌曲播放完毕自动播放下一首
- 上一首/下一首：切换到队列中上一首/下一首歌曲；已在队列首尾时按钮置灰
- 播放/暂停：点击切换播放状态，图标同步切换（播放图标 ↔ 暂停图标）
- 进度条：
  - 实时显示当前播放进度（`currentTime / duration`）
  - 支持拖拽定位到指定时间点
  - 拖拽时暂停实时更新，松手后从新位置继续播放
- 音量滑块：
  - 范围 0-100，默认 80
  - 拖动实时改变音量

**业务规则**：
- 使用毛玻璃效果（backdrop-blur + 半透明白色背景）
- 播放器使用全局单例的 `<audio>` 实例，跨页面共享，切页面不中断播放
- 播放状态（当前歌曲、播放进度、音量）存储在 Pinia store 中，页面切换后恢复
- 音频加载失败时（如文件 404），自动跳到下一首并提示"音频文件不可用"
- 队列中所有歌曲播放完毕后，播放器回到空队列状态

**优先级**：高

### 3.3 图片资源展示与回退规则（通用）

**适用范围**：所有展示头像或封面图片的位置，包括管理端账户列表、编辑弹窗、歌曲列表、歌曲详情页、Web 端歌曲卡片。

**封面展示形状**：
- 所有位置的封面图片统一以 **1:1 正方形**展示
- 使用 `object-cover` 裁剪填充，圆角根据容器定义
- 不得使用圆形、圆角矩形等非正方形形状展示封面

**头像展示形状**：
- 所有位置的头像图片统一以 **圆形**展示

**文件回退规则**：

| 场景 | 行为 |
|------|------|
| 未上传自定义图片 | 显示默认图（头像：`/uploads/avatars/default.jpg`，封面：`/uploads/covers/default.jpg`） |
| 已上传但文件被物理删除（404） | 回退显示对应的默认图 |
| 默认图也被删除（404） | 浏览器显示裂图（原生 broken image 表现） |

**前端实现要求**：
- `<img>` 标签的 `src` 指向数据库中存储的 URL（自定义路径或默认路径）
- 绑定 `@error` 事件：当图片加载失败时，将 `src` 切换为默认图 URL
- 如果默认图也加载失败，不做额外处理，由浏览器显示原生裂图
- **不得**回退到首字母、音符图标等非图片元素

**优先级**：高

## 6. 非功能性需求

### 6.1 性能
- 页面首次加载时间 < 3 秒（本地开发环境）
- API 接口响应时间 < 500ms（Mock 数据模式）
- 列表分页加载，单页不超过 10 条

### 6.2 兼容性
- 支持 Chrome 最新版本（主要开发和测试浏览器）
- 支持 Edge 最新版本

### 6.3 安全性
- 密码不得明文存储，使用哈希算法
- API 接口使用 JWT Token 认证
- 敏感操作（退款、取消、删除订单、余额调整）需要确认弹窗
- 二级密码验证：删除订单、余额调整操作需输入当前管理员密码二次确认

### 6.4 可用性
- 所有交互操作提供视觉反馈（按钮按下缩放 98%）
- 加载中状态显示骨架屏或加载指示器
- 操作结果使用消息提示（成功/失败）

### 6.5 代码质量
- 前端使用 TypeScript 严格模式
- 后端使用 C# 强类型
- API 接口统一错误格式返回
